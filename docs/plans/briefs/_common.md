# Common rules for every Recipe Keeper stream agent

- You run in a **git worktree** created by herdr, branched from `recipekeeper/main` (contains WS0 scaffold + WS1 engine upgrade). `docs/plans/*.md` are committed in your checkout; read them by relative path. Read `CLAUDE.md` first.
- **Base state you can rely on:** `:core:web` contracts (`com.llmlocal.core.web.*`, bodies `TODO("WS2")`), `:feature:webclipper` contracts (`com.llmlocal.feature.webclipper.*`, MVI in `.mvi`, DI in `.di`, routes render `Text("WS4")`), `:app:recipekeeper` scaffold (`com.llmlocal.recipekeeper.*`: domain types, minimal Room DB, placeholder library screen, `RecipeKeeperTokens` still the recipes palette), `LlmRequest` + `LlmEngine.generateStream(request)` + real cancel in the engine, `FakeLlmEngine` in `core/llm/src/test`.
- **WS0 contract adjustments** (differences from the plan text): `ExtractionEffect.NavigateToSaved(id)` (not `NavigateToRecipe`); `BrowserState.readiness: Any?` is a placeholder until WS3's `ModelReadiness` lands; `ClipFabState.ModelNotReady(download: PerModelProgress?)`; `BrowserIntent.UrlFocusChanged(focused)` exists; routes take a trailing `modifier`; `RecipeSummary(id, title, sourceHost, totalMinutes, heroPicture, truncated, clippedAt)`; `ExtractionError { ModelFailed(reason), ParseFailed(rawOutput), ModelMissing }`; `PictureDraft(url, localFile, keep, status)`.
- **WS3 is running in parallel on another branch** and will add: `com.llmlocal.core.llm.readiness.{ModelReadiness, ModelReadinessObserver}`, three new `ModelManagementLabels` snackbar fields, `AppErrorView(retryLabel)`, and design-system primitives `PhaseProgress`, `StreamingText`, `StreamingCursor`, `SkeletonLine`, `SectionHeader`, `NumberBadge`. Do not implement those yourself; where you need them, add a clearly marked local shim (`// TEMP shim: replaced by WS3 at merge`) with the same API shape so the lead can swap imports.
- **Device:** a single `emulator-5554` (arm64, ~220 MB free) is shared by several agents. **Do not install or launch apps**; build + unit tests + Compose previews only. The lead does device QA in WS6.
- Keep `./gradlew :app:recipes:assembleDebug :app:medical:assembleDebug :app:recipekeeper:assembleDebug` green. Run the unit tests of the modules you touch. Run `./gradlew <module>:dependencies --configuration releaseRuntimeClasspath` if you add a project dependency and confirm no `:feature → :app` or `:core → :feature` edge.
- Edit only files you own (listed in your brief). If you must change a shared contract, do it minimally, keep old signatures compiling where possible, and list every change in your report.
- Code style: match the repo (KDoc headers, MVI naming, string-style `project(":x:y")`, `@Immutable` labels, no hardcoded brand colors or copy in `:core`/`:feature`).
- `org.json` is a stub on the JVM: for unit tests that touch `JSONObject`, add `testImplementation("org.json:json:20250517")` via a catalog entry `org-json` (WS2 adds the catalog entry; others reuse it if already present, else add the same one).
- When finished: **commit on your worktree branch only** (never master or `recipekeeper/main`, never push), message ending `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`. Write `docs/plans/briefs/<your-id>-report.md` in your worktree (files, public signatures, tests/builds run with results, shims added, anything the lead must do at merge) and include it in the commit. Then reply in the terminal with `<your-id> done — see <your-id>-report.md, branch <branch>, commit <hash>`.
- Make routine decisions yourself and record them; only stop if truly blocked.
- **NO HARDCODED USER-VISIBLE STRINGS (user, 2026-10-19, non-negotiable):** every user-visible string comes from `res/values/strings.xml` via `stringResource`/`getString`/`pluralStringResource`; label data classes are built from resources in the app module and have no default literals; feature modules may ship their own `strings.xml` for brand-neutral copy. A Kotlin string literal that reaches the UI, a notification or a share intent is a bug. See CLAUDE.md Architecture rule 0.
- **Architecture rules (user, 2026-10-19):** ViewModels take use cases, never repositories/stores/engines/downloaders; every feature is one package with `presentation/`, `domain/`, `data/` sub-packages (`presentation → domain ← data`, `domain` pure Kotlin). Do not add a new dependency to a ViewModel constructor unless it is a use case; when you touch existing code that breaks these rules, migrate what you touch. See CLAUDE.md "Architecture rules".
- **Instrumented tests on a device that holds data you must keep (the model, a library fixture): never run `./gradlew connectedDebugAndroidTest` — AGP uninstalls the app afterwards and wipes its data (F4 QA incident, 2026-10-20).** Install the test APK by hand instead (`adb install -t -r <app>-debug-androidTest.apk` next to the installed app, then `adb shell am instrument -w -e class <FQN> <appId>.test/androidx.test.runner.AndroidJUnitRunner`), or use a throwaway AVD.
