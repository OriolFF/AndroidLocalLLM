# Brief — R3: refactor `:feature:webclipper`
Read `docs/plans/briefs/refactor-common.md` first.
**You own:** `feature/webclipper/**` only. `:app:recipekeeper` (another agent) implements `WebClipConfig<T>` / `ClipSink<T>` and calls the two routes; keep those contracts' **semantics** identical — you may move their packages (report old → new FQNs) and add default members, nothing else.
Current shape: root package has `WebClipConfig`, `ClipSink`, `ClipCandidate`, `WebClipperLabels`, `ClipSession`, `WebViewHolder`, `BrowserViewModel`, `ExtractionViewModel`, `TruncationHeuristic`, `WholePageCandidate`, routes; `capture/` (`PageScanner`, `PictureDownloader`), `readiness/`, `mvi/`, `ui/`, `previews/`, `di/`. `BrowserViewModel(config, labels, scanner, session, readinessSource, dispatchers, initialUrl)`; `ExtractionViewModel(candidateId, config, sink, labels, session, generateTask, engine, pictureDownloader, tempDir, dispatchers)` orchestrates engine init, generation, fallback, acceptance, duplicate check, picture downloads, truncation, saving.
Do:
1. Packages: `domain/` (contracts `WebClipConfig`, `ClipSink`, `ClipCandidate`, `CandidatePayload`, `WholePageCandidate`, `TruncationHeuristic`, `ClipSession` interface, source interfaces, use cases), `data/` (`WebViewHolder`, `WebViewPageScanner`, `ImageDownloaderPictureDownloader`, readiness adapter, `ClipSession` impl, temp-dir picture store), `presentation/{mvi,ui,previews}` (routes, screens, ViewModels, labels), `di/`.
2. Use cases (domain): `ScanPageUseCase` (quick scan + full capture → candidates via config), `ObserveReadinessUseCase`, `ClipUseCase<T>` — the whole extraction pipeline as a `Flow<ClipProgress>` (phases, token deltas, pictures, fallback, accept, truncation, save; sealed `ClipProgress` events replace the ViewModel's inline orchestration), `CheckDuplicateUseCase` (`sink.existingId`), `CancelClipUseCase`, `RetryPicturesUseCase` is NOT here (app-level). Keep `LlmRequestOptions` use via `GenerateLlmTaskUseCase` inside a `data/` adapter implementing a domain `LlmGenerationSource`.
3. `BrowserViewModel(config, labels, scanPage, observeReadiness, session?, dispatchers, initialUrl)` — if the session must be shared between the two ViewModels, model it as a domain `ClipSessionSource` interface injected into both (allowed: it is a domain interface, not a data class). `ExtractionViewModel(candidateId, config, sink, labels, clip: ClipUseCase<Any>, checkDuplicate, cancelClip, dispatchers)`.
4. `di/WebClipperModule.kt`: `webClipperModule` binds adapters → interfaces, use cases `factory`, ViewModels with the same `parametersOf(...)` the routes pass today.
5. Update all tests in `feature/webclipper/src/test` and `src/androidTest` to the new shapes (fakes implement domain interfaces; `ExtractionViewModelTest` becomes mostly `ClipUseCaseTest` + a thin ViewModel test). Run once at the end: `:feature:webclipper:testDebugUnitTest` and `:app:recipekeeper:assembleDebug` (expect the app to break only on moved imports — list them; do not edit the app).
Report `docs/plans/briefs/r3-report.md` with every moved FQN and the final route/contract signatures.
