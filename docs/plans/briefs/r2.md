# Brief — R2: refactor `:feature:modelmanagement`
Read `docs/plans/briefs/refactor-common.md` first.
**You own:** `feature/modelmanagement/**` only.
Current shape: `com.llmlocal.feature.modelmanagement.{ModelManagementViewModel, ModelManagementRoute, ModelManagementScreen, components/, mvi/, di/, ModelDownloadScheduler, WorkInfoObserver}`; the ViewModel injects `LlmModelManager`, `LlmModelSelectionStore`, `ModelDownloadProgressStore`, `ModelDownloadScheduler`, `WorkInfoObserver`.
Do:
1. Packages `presentation/{mvi,components}`, `domain/`, `data/`, `di/`.
2. `domain/`: domain model `ModelListing` (descriptor + installed + selected + progress) if it simplifies state building; interfaces `ModelCatalogSource` (`all(): List<LlmModelDescriptor>` — `LlmModelDescriptor` is `:core:model`, pure Kotlin, allowed), `InstalledModelsSource` (`installedIds(): Set<String>`, `remove(id)`), `ModelSelectionSource` (`selectedId: Flow`, `select(id)`), `DownloadProgressSource` (`progress: Flow<Map<String, PerModelProgress>>` → map `PerModelProgress` to a domain `DownloadProgress` type), `DownloadScheduler` (`enqueue(id)`, `cancel(id)`), `DownloadWorkSource` (`observe(): Flow<...>` mapped from `WorkInfo` to a domain status). Use cases: `ObserveModelListingsUseCase` (combines catalog + installed + selection + progress + work status into one `Flow<List<ModelListing>>`), `DownloadModelUseCase`, `CancelDownloadUseCase`, `SelectModelUseCase` (returns a sealed result: `Selected` / `NotInstalled` so the ViewModel can pick the snackbar label), `RemoveModelUseCase`, `FilterModelsUseCase` (pure: family/size/quant/status filters currently in the ViewModel).
3. `data/`: adapters over `LlmModelCatalog`, `LlmModelManager`, `LlmModelSelectionStore`, `ModelDownloadProgressStore`, `ModelDownloadScheduler` (move it to `data/`), `WorkInfoObserver` (move to `data/`).
4. `ModelManagementViewModel(observeListings, downloadModel, cancelDownload, selectModel, removeModel, filterModels, dispatchers, labels)`; same `ModelManagementState`/effects/snackbars.
5. `di/ModelManagementModule.kt`: `modelManagementModule` — adapters bound to interfaces, use cases `factory`, ViewModel with `parametersOf(labels)` as today. Keep `DownloadProgressBar` public (the Recipe Keeper library screen uses it) under `presentation/components`.
6. Tests: update/add `ModelManagementViewModelTest` (fakes for the domain interfaces: listing combines sources; select not-installed → snackbar label; remove → effect) and a `FilterModelsUseCaseTest`. Run once at the end with `:feature:modelmanagement:testDebugUnitTest :app:recipes:assembleDebug`.
Report `docs/plans/briefs/r2-report.md` with the moved FQNs (apps import `ModelManagementRoute`, `ModelManagementLabels`, `DownloadProgressBar`, `modelManagementModule`).
