# Strings migration — common rules (CLAUDE.md Architecture rule 0)
You are one of four parallel agents moving every user-visible string into Android resources. Base: `recipekeeper/main` (your worktree). Read `CLAUDE.md` rule 0 first, then `docs/plans/briefs/_common.md`, then your brief. Edit only the files your brief assigns; other agents are working in parallel.

## The rule
No hardcoded user-visible string anywhere: labels, buttons, titles, snackbars, dialogs, notifications, content descriptions, error messages shown to users, placeholders, chips, share text, preview copy. Allowed literals: log messages, exception messages that never reach the UI, URLs/ids/keys, JS/HTTP headers, **model-facing prompt text** (system/user prompts are not UI; keep them in Kotlin), test fixtures.

## How
- **Resources per module.** Put strings in `res/values/strings_<area>.xml` (one file per stream, e.g. `strings_llmtask.xml`, `strings_modelmanagement.xml`, `strings_webclipper.xml`, `strings_recipekeeper.xml`) so parallel streams never edit the same file. Android merges all `values/*.xml`. Key style: `<area>_<screen>_<element>` in lower_snake_case (e.g. `webclipper_fab_clip`, `recipekeeper_library_empty_title`). Use `<plurals>` for count-dependent text and `%1$s`/`%1$d` placeholders for formatted text. Keep the English text exactly as today (byte-identical copy; this is a refactor, not a rewording).
- **Label data classes lose every default value.** Keep the class and field names (they are the feature↔brand contract); make all fields required. Lambda fields (`(Int) -> String`, `(String, String) -> String`) stay lambdas.
- **Labels are built from resources in the module that owns the copy:**
  - In an app: `@Composable fun rememberRecipeLabels(): LlmTaskLabels` (uses `stringResource`, `pluralStringResource`, and for lambdas captures `LocalContext.current.resources` and calls `getString(R.string.x, arg)` / `getQuantityString`). Also provide a non-composable `fun recipeLabels(resources: Resources): LlmTaskLabels` when a ViewModel/worker/`Application` needs it. Pass the result where the old `val RecipeLabels` object was used (routes, `parametersOf`, previews).
  - In a feature module, for brand-neutral copy the feature itself renders (and for its previews): the feature's own `res/values/strings_<area>.xml` + a `@Composable fun defaultXLabels(): XLabels` in the feature. Feature modules already have `androidResources = true` via the library convention plugin; add `namespace`-based `R` imports as needed.
  - Non-Compose code (`ModelDownloadWorker` notifications, snackbar strings produced in ViewModels): receive the strings through the labels object or `context.getString` with the module's own resources. ViewModels must not hold a `Context`; pass the formatted strings in via labels built in the app/route.
- **Content descriptions** (`contentDescription = "Back"`) and `semantics { contentDescription = … }` are user-visible: resources.
- **Previews**: use the resource-built labels (`rememberXLabels()` / `defaultXLabels()`); sample *data* (recipe titles, ingredient lines, URLs) may stay literal because it is fixture content, not copy.
- **Tests**: unit tests may construct label objects with literal strings (fixtures) — add a `test` helper (e.g. `TestLabels.kt`) with a full label instance so tests keep compiling; do not add Android resource access to JVM tests.
- Do not change behaviour, layout or wording. Do not touch `:core:domain`, `:core:common`, `:core:model`, `:core:network`.
- **Verify once at the end** (no per-step test runs): your modules' `testDebugUnitTest` + `./gradlew :app:recipes:assembleDebug :app:medical:assembleDebug :app:recipekeeper:assembleDebug`, then a literal scan over your files: `grep -rnE '"[A-Z][a-zA-Z ,.…!?'"'"'-]{3,}"' <your dirs> --include='*.kt' | grep -v -i 'log\.\|exception\|require(\|prompt\|test'` must show only allowed literals (list each remaining one in your report with the reason).
- Commit per logical step on your worktree branch; final commit includes `docs/plans/briefs/<id>-report.md` (resource files added, label factories, remaining allowed literals with reasons, moved/changed public signatures, test/build results). Reply `<id> done — see <id>-report.md, branch <branch>, commit <hash>`.
