## New bugs

### A. (P2) Collection pages with a recipe-ish URL path offer every card as a "Text" candidate
**Seen** on `tasteofhome.com/collection/recipes-with-ground-beef/` (`26-toh-after-tap.png`): a `Which recipe?` sheet with 10 candidates, all `Text · 2 ingredients`; each tap runs the model (~7 s) and ends on the parse-failed screen. WS11's bug-3 fix removes the Tier A stubs and the accept floor stops the save, but the sheet still presents ten non-recipes as recipes. 
**Cause.** `detectText()` lowers the quantity-line threshold from 3 to 2 whenever `hasRecipePath(url)` matches (`app/recipekeeper/.../clip/RecipeKeeperClipConfig.kt:118`, regex at `:492` matches any `recipe|recipes|…` substring, so `/collection/recipes-with-ground-beef/` qualifies); every card section on the collection has two quantity-looking lines ("1 lb ground beef", "2 cups rice"), so `isRecipeSection` (`:149-151`) accepts all of them, capped at 10. 
**Fix.** Keep the relaxed threshold only when it finds a *single* section: run the strict pass (`MIN_QUANTITY_LINES`) first; if it yields nothing and the path is recipe-ish, run the relaxed pass and accept it only when `picked.size == 1` (a real recipe page has one ingredient block; a list page has many). Also make `recipePath` not match list-style paths (`collection|collections|category|tag|search|gallery|roundup` anywhere in the path → `false`). Add a `RecipeKeeperClipConfigTest` fixture with ≥ 5 two-line card sections under a `/collection/recipes-…/` URL expecting `detect` to be empty, and keep the existing single-section relaxed case green.

### B. (P2) "Clip cancelled" and "Saved to your recipes" are dismissed with the navigation transition
**Seen** every time: `Clip cancelled` visible at +0.3 s after Stop and gone at +1.0 s (`14-after-stop-0.3s.png` → `14-after-stop-1s.png`); `Saved to your recipes` visible for ≈1.2 s around the extraction → detail cross-fade and gone the frame the transition ends (`snack2/s10…s17`, brightness series in this report's QA3 folder). A Short snackbar should stay ~4 s. 
**Cause.** `WebClipperExtractionRoute.kt:75-77` launches `host.showSnackbar(...)` **inside the `LaunchedEffect(viewModel)` collector**; the next effect in the channel (`PopToBrowser` → `popBackStack`, or `NavigateToSaved` → `navigate { popUpTo(browser) }`, `MainActivity.kt:144-149`) removes the destination, the `LaunchedEffect` is cancelled when the composable leaves composition at the end of the transition, and cancelling the coroutine that called `showSnackbar` dismisses the snackbar. WS11 correctly stopped *awaiting* it (so the pop is immediate) but the child job still dies with the route. The detail route's `Recipe deleted` snackbar avoids this by launching in the root scope (`MainActivity.kt:170-172`, "Launched in the root scope so the snackbar outlives the popped screen"). 
**Fix (feature + app, additive).** Give `WebClipperExtractionRoute` an `onShowSnackbar: ((String) -> Unit)? = null` parameter (or a `snackbarScope: CoroutineScope`) and route `ExtractionEffect.ShowSnackbar` through it when present, falling back to the current `launch` otherwise; in `MainActivity.kt:130-154` pass `onShowSnackbar = { msg -> scope.launch { snackbarHostState.showSnackbar(msg) } }` using the existing root `scope` (`MainActivity.kt:85`). Same pattern is worth applying to the browser route's `BrowserEffect.ShowSnackbar` (`WebClipperBrowserRoute.kt:119` awaits it inline — fine for the browser, which never pops itself, but it serialises effects behind a 4 s snackbar). Device re-check: `Clip cancelled` must still be on the browser at +3 s; `Saved to your recipes` on the detail at +3 s.

### C. (P3) The draft card's "Waiting for the first words…" line disappears before any readable token
`04-clip1-01.png` (+0.6 s) shows `Waiting for the first words from the model…` + cursor; from `04-clip1-04.png` (+2.8 s) to `-12.png` (+10.9 s) the card shows the skeleton with a bare cursor and no text, although nothing parseable has arrived (the first token is `{`/whitespace under the JSON response format). `ClipDraftCard.kt:292-298` switches on `streamedText.isBlank()`, so one byte removes the hint, and `tail` is blank because the parser consumed it. 
**Fix.** Show `labels.draftWaiting` while the parsed draft is still empty (`draft.title == null && draft.ingredients.isEmpty() && draft.steps.isEmpty()`) and `tail.isBlank()`, regardless of `streamedText`. (Observation: on the first run of a prompt the whole recipe landed between +11 s and +12 s; on later identical prompts tokens were visible by +2.5 s (`14-before-stop.png` shows title, description, chips and 3 ingredients at +2.5 s) — LiteRT-LM apparently reuses the prefix, so the skeleton-until-the-end case is the cold path.)

### D. (P3) "Retry pictures" brings in pictures the clipper would have left unchecked
After the online retry the BBC recipe `cfd12f16…` has 3 pictures (`001–003.jpg`), whereas a normal online clip of the same page keeps 1 (only the node image is preferred; the two "related recipe" card images are offered unchecked). `ExtractionViewModel.kt:332` stores *every* proposed URL as `pictureCandidates` and `RecipeDetailViewModel.kt:120` downloads the first `RETRY_PICTURES` (3). 
**Fix.** Store the picks the user had checked at save time (fall back to the preferred picks) as `pictureCandidates`, or store `PicturePick` order with preferred first and let the retry take `preferred` ones only. Detail pager screenshot not taken; the count comes from the `pictures` table.
