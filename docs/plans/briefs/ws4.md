# Brief — WS4: `:feature:webclipper` (browser, clip FAB, candidate sheet, extraction screen)
Read `docs/plans/briefs/_common.md` first, then `docs/plans/recipekeeper-app-plan.md` §2.3, §3, **WS4** in section 4, and `docs/plans/recipekeeper-ux-spec.md` §2–§4, §6, §9 (this is your UI spec; follow it closely). Also read `.claude/agents/android-ux.md` and apply its rules to every composable; if that subagent type is available in your session, use it to review your screens.

**You own:** `feature/webclipper/**`; plus a minimal repository overload: `core/domain/.../repository/LlmTaskRepository.kt`, `core/domain/.../usecase/GenerateLlmTaskUseCase.kt`, `core/data/.../repository/LlmTaskRepositoryImpl.kt` (add `LlmRequestOptions(systemInstruction: Boolean /* send systemPrompt as systemInstruction instead of concatenating */, maxOutputTokens: Int?, temperature: Double?, jsonSchema: String?)` and an overload `generateStream(engine, config, inputs, options)`; the old 3-arg call keeps its exact behaviour). Do not edit `core/llm`, `core/web` (WS2 is implementing it; code against its contracts and use fakes), or any `app/`.

Steps (details in the plan and UX spec):
1. `WebViewHolder` (application context, one `WebView`, settings per research §B: JS + DOM storage on, file/content access off, safe browsing on, mixed content NEVER_ALLOW; `WebViewClient` keeps http/https, hands `intent:/mailto:/tel:` to the system, `onRenderProcessGone` recreates; `WebChromeClient` progress/title; `doUpdateVisitedHistory`; `saveState/restoreState`; lifecycle `onPause/onResume/destroy`).
2. `BrowserViewModel` (state/intents/effects already in `.mvi`): URL submit with scheme inference and search fallback (`labels.searchUrlTemplate`), progress, proactive `quickScanStructured` after load (debounced ~1.5 s), `Scan` → `PageCapture.capture` → `config.detect` → `ClipSession.set` → `Found(n)` or sheet; `ModelNotReady` tap → `NavigateToModelManagement`; FAB collapse on scroll; hide while IME visible. Readiness: add `// TEMP shim` `feature/webclipper/.../readiness/ModelReadiness.kt` mirroring plan §2.4 (`sealed interface ModelReadiness { NoModel; Checking; Downloading(progress); Initializing; Ready(descriptor); Failed(reason, descriptor?) }`) and inject a `ReadinessSource { fun observe(scope): StateFlow<ModelReadiness> }` so the lead can swap to WS3's observer; change `BrowserState.readiness` to this type.
3. `ExtractionViewModel`: candidate from `ClipSession`; phases Reading→Extracting→Pictures→Saving; `GenerateLlmTaskUseCase(engine, config.llmConfig, listOf(config.renderLlmInput(...)), LlmRequestOptions(systemInstruction = true, maxOutputTokens = config.maxOutputTokens, temperature = 0.2))`; append `streamedText`; pictures via `config.pickPictures` + `ImageDownloader` in parallel (`async`, non-blocking failures → Pictures phase Warning); on `Complete` → `sink.save` → `NavigateToSaved(id)`; on parse failure → `config.fallback()` for STRUCTURED else `ParseFailed`; `Cancel` → cancel job + `engine.cancel()` + delete temp files + `PopToBrowser`; truncation heuristic (buffer ends mid-sentence and output length ≈ cap) → `truncated = true` with Warning.
4. Composables per UX spec: `WebClipperBrowserScreen` (own `Scaffold`, `BrowserTopBar` URL pill, 2dp progress, `AndroidView(WebView)` with `imePadding()`/`navigationBarsPadding()`, `ClipFab` with `AnimatedContent` over `ClipFabState`, `CandidateSheet`, `NothingDetectedSheet`), `WebClipperExtractionScreen` (phase list, source strip, `renderDraft` slot, picture strip with keep checkboxes, Stop, error states table). For `PhaseProgress`, `SkeletonLine`, `StreamingCursor` add `// TEMP shim` private composables in the feature with the WS3 API shape (`PhaseProgress(items: List<PhaseItem>)`, `PhaseItem(label, status: PhaseStatus)`), to be replaced at merge. `BackHandler` for WebView history. Accessibility per UX spec §9.
5. `webClipperModule`: `viewModel { params -> BrowserViewModel(...) }`, `viewModel { params -> ExtractionViewModel(...) }` using `parametersOf(config, sink, labels, …)` from the routes (same pattern as `llmTaskModule`); real engine via `get(named(REAL_ENGINE_QUALIFIER))`.
6. Tests (`feature/webclipper/src/test`, Turbine + coroutines-test): `BrowserViewModelTest`, `ExtractionViewModelTest` with `FakePageCapture`, `FakeLlmEngine` (copy the class from `core/llm/src/test` into your test sources), `FakeClipSink`, `FakeImageDownloader`: single candidate skips the sheet; multiple opens it; not-ready blocks scan and emits navigate; cancel deletes temp files; STRUCTURED parse failure uses fallback; picture failure non-blocking; truncation flag.
Done when: feature builds, tests green, previews exist for every FAB state, both sheets and the extraction screen in light/dark, report written (including the exact shim files the lead must replace).
