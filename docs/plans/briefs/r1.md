# Brief — R1: refactor `:feature:llm-task` (+ `:app:recipes`, `:app:medical` importers)
Read `docs/plans/briefs/refactor-common.md` first.
**You own:** `feature/llm-task/**`, `app/recipes/**`, `app/medical/**`.
Current shape: `com.llmlocal.feature.llmtask.{LlmTaskViewModel, LlmTaskRoute, LlmTaskScreen, components/, mvi/, di/}`; `LlmTaskViewModel(generateTask, selectionStore, readinessObserver, realEngine, dispatchers, config, labels)` injects `:core:llm` stores and the engine directly.
Do:
1. Create `feature/llmtask/{presentation,domain,data,di}`. Move UI + MVI + labels to `presentation` (`presentation/mvi`, `presentation/components`).
2. `domain/`: interfaces `ModelReadinessSource` (`observe(scope): StateFlow<ModelReadiness>`, `recheck()`), `SelectedModelSource` (`selectedModelId: Flow<String?>`, `current(): String`), `LlmGenerationSource` (wraps engine init + `GenerateLlmTaskUseCase` behind one interface), plus use cases: `ObserveModelReadinessUseCase`, `ObserveSelectedModelUseCase`, `RecheckModelUseCase`, `GenerateTaskUseCase<T>` (streams `LlmTaskEvent<T>` for inputs; owns the engine `initialize()` call), `CancelGenerationUseCase`. `ModelReadiness` itself lives in `:core:llm` — re-export via a domain model or depend on the core type only inside `data/` adapters and map to a domain enum/sealed type in `domain/` (prefer mapping: domain must not import `:core:llm`; `:core:domain` types like `LlmTaskEvent`, `LlmTaskConfig` are allowed since `:core:domain` is pure Kotlin).
3. `data/`: adapters over `ModelReadinessObserver`, `LlmModelSelectionStore`, `LlmEngine` + `GenerateLlmTaskUseCase`.
4. `LlmTaskViewModel(observeReadiness, observeSelectedModel, recheckModel, generateTask, cancelGeneration, dispatchers, config, labels)`; same `LlmTaskState`/`ModelStatus` mapping as today.
5. `di/LlmTaskModule.kt`: `llmTaskModule` binds data adapters to domain interfaces, use cases as `factory`, ViewModel via `parametersOf(config, labels)` as today.
6. Update `app/recipes` and `app/medical` imports to the new packages; also move their own code into feature packages: `app/recipes/.../recipe/{recipe/presentation (RecipeScreen, StreamedRecipeCard, previews), recipe/domain (Recipe, RecipePromptBuilder, RecipeParser), config, designsystem}` — same for medical (`MedicalAdvice`, …). Keep `MainActivity`, `RecipeApp`/`MedicalApp` at the package root.
7. Tests: update `core`-independent tests in `feature/llm-task/src/test` (there may be none; add `LlmTaskViewModelTest` with fakes of the domain interfaces: readiness → Ready enables generate; generation events → streamedText/result; cancel resets). Run once at the end with `:feature:llm-task:testDebugUnitTest :app:recipes:assembleDebug :app:medical:assembleDebug`.
Report `docs/plans/briefs/r1-report.md`.
