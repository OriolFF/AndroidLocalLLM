# Brief — R4: refactor `:app:recipekeeper` into features with presentation/domain/data
Read `docs/plans/briefs/refactor-common.md` first.
**You own:** `app/recipekeeper/**` only. `:feature:webclipper` is being refactored in parallel (packages of `WebClipConfig`, `ClipSink`, routes and labels may move); code against the **current** FQNs and note in your report which imports will need a sed after merge.
Current shape (`com.llmlocal.recipekeeper`): `clip/` (config, sink, mapper, text cleaner), `parser/`, `prompt/`, `domain/` (ClippedRecipe, RecipeSummary, RecipeDraft, RecipeRepository), `data/` (Room, RoomRecipeRepository, RecipePictureStore, converters), `library/` (LibraryViewModel + screen + PendingRecipeDeletes + ModelStatusSource), `detail/` (RecipeDetailViewModel + screen), `output/` (ClipDraftCard, StubDraftParser), `config/` (labels, Koin modules), `designsystem/`, `previews/`, `MainActivity`, `RecipeKeeperApp`.
Target:
```
recipekeeper/
  app/            MainActivity, RecipeKeeperApp, navigation (RecipeKeeperNavHost), di/ (aggregates feature modules)
  designsystem/   tokens
  recipes/        feature "recipes" (library + detail + shared recipe domain)
    presentation/ library/, detail/, labels, previews
    domain/       ClippedRecipe, RecipeSummary, RecipeRepository (interface), use cases
    data/         Room db/dao/entities/converters, RoomRecipeRepository, RecipePictureStore, ModelReadiness adapter
    di/           recipesModule
  clip/           feature "clip" (how this brand clips: config, sink, mapper, prompt, parsers, draft card)
    presentation/ ClipDraftCard, draft previews, RecipeKeeperClipperLabels
    domain/       RecipeKeeperClipConfig, SchemaOrgRecipeMapper, TextCleaner, RecipeKeeperPromptBuilder, parsers, RecipeDraft, RecipeKeeperTaskConfig
    data/         RecipeKeeperClipSink (needs repository + picture store)
    di/           clipModule
```
Use cases (recipes/domain): `ObserveLibraryUseCase` (list + search), `ObserveRecipeUseCase`, `ToggleIngredientCheckedUseCase`, `ResetChecksUseCase`, `DeleteRecipeWithUndoUseCase` (absorbs `PendingRecipeDeletes`: `schedule/undo/commit`, app-scoped), `RetryRecipePicturesUseCase` (download via a domain `PictureFetcher` interface + `RecipePictureStore` interface + repository), `ShareRecipeUseCase` (builds the share text from labels), `ObserveLibraryModelStatusUseCase` (replaces `ModelStatusSource`; adapter in data over `ModelReadinessObserver`). `LibraryViewModel(observeLibrary, observeModelStatus, deleteWithUndo, shareRecipe, dispatchers)`, `RecipeDetailViewModel(recipeId, observeRecipe, toggleIngredient, resetChecks, deleteWithUndo, retryPictures, shareRecipe, dispatchers)`.
Rules: `domain/` packages are pure Kotlin (Room entities stay in `data/`; `RecipeRepository` interface in `domain/`); `presentation` never imports `data`. Koin: `recipeKeeperConfigModule` and `recipeKeeperUiModule` may be replaced by `recipesModule` + `clipModule` + an `app/di/appModules` list — keep `RecipeKeeperApp` wiring compiling. Keep the `schemas/` export and DB version as they are (just moved). Update `src/test` to the new packages/constructors (fakes implement the domain interfaces; keep the eval tests under `src/test/.../clip/eval` or similar and their resources paths unchanged). Run once at the end: `:app:recipekeeper:testDebugUnitTest :app:recipekeeper:assembleDebug`.
Report `docs/plans/briefs/r4-report.md` with the final tree, use cases, Koin modules, and the list of `feature.webclipper` imports you used.
